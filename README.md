## 2026-10-24：UART 十六进制解码与轮轴中文看板

在原有页面新增「日志解码」，支持粘贴串口助手的 `收←◆` HEX接收日志、普通文本，以及导入最多2 MiB的txt/log文件。自动去掉接收时间戳、排除 `发→◇` 命令，跨接收片段拼接字节，再以UTF-8或GB18030/GBK解码。控制字节、不完整十六进制片段、截断窗口会明确提示，不补造缺失数据。

点击「解码并分析」后，可复制文本、下载TXT、导出全部解析窗口CSV。原始字段保持不变，页面显示中文学习状态、RMS/峰值（mg）、主峰（Hz）、波峰因数、峭度、学习进度、固件报警标志与趋势。趋势跳号处断线；表格展示最近200个有效窗口，CSV保留本次全部解析窗口。粘贴解析与下方实时串口会话分开，粘贴区不自动保存，请离开前导出。

现在实时串口也支持轮轴固件的 `win=...` 文本，不需要改CPU输出格式；原JSON协议和模拟演示继续可用。完整轮轴字段随实时采集的浏览器备份保存，恢复时保留。实时CSV追加轮轴字段，普通JSON会话的原CSV格式不变。

示例报文：

```text
win=82 fs=200 n=512 rpm_ref=280 rms_mg=76 peak_mg=913 crest_x1000=12013 kurt_x1000=64075 peak_mHz=1171 f1_permille=28 h23_permille=44 base=12 flags=0 status=NO_THRESHOLD_EXCEEDED overrun=0 max_read_us=1173 analysis_us=72882
```

最低完整轮轴窗口须含 `win/rms_mg/peak_mg/base/flags/status`；其他字段未提供时显示缺失，不当作0。`base=12`是学习数量，不是基准RMS。`rpm_ref`是配置值，主峰不是实测转速。`NO_THRESHOLD_EXCEEDED`译为「未超过当前门限」，不宣称设备健康；`flags`按位组合解释为振动增强、疑似不平衡、疑似松动、疑似冲击/轴承异常。`INVALID reason=1～5`与`ERROR INIT`单独解释。后续错误事件会覆盖旧窗口的状态，避免基准已清除却仍显示监测正常。

所有解码、图表、导入导出在本机浏览器完成，没有日志上传接口。Web Serial仍需要用户点击连接并授权；浏览器连接收到的是CPU文本，不需要先在串口工具里开启HEX显示。使用串口助手粘贴历史日志时，可保留原HEX格式。

## 保存与备份数据

- **自动保存**：保留最近 10,000 帧、最近 120 行原始报文，以及接收总数、异常
  报文数和会话起始时间。暂停图表时仍继续保存；切换到后台、关闭页面或停止
  采集时会尝试立即保存。突然断电或浏览器崩溃可能丢失最后一秒未保存的数据。
- **一键导出 CSV**：在「数据记录」右上方下载当前保留的数据，可用 Excel 等
  表格软件打开，包含时间、来源、序号、处理结果及状态。
- **导出完整备份**：下载 JSON 文件，包含保留的数据、原始报文和统计。
  可保存到本地，或自行上传到 GitHub 仓库的 `data/` 目录留档。
- **导入备份**：停止演示或断开串口后，选择本站导出的 JSON 文件（最多 8 MB），
  即可恢复到页面。导入会覆盖当前记录，已有记录时需要确认；损坏或不兼容的
  文件会被拒绝，当前记录不变。

自动保存只属于当前设备、当前浏览器及当前网站地址，不会自动同步到 GitHub
或其他设备。浏览器清理网站数据、无痕窗口关闭或浏览器回收存储可能清除备份，
重要记录请额外导出文件。页面显示上次保存时间，存储不可用或空间不足时会提示
立即导出。多个标签页修改同一份备份时，检测到冲突的页面会暂停自动保存，
请先导出本页记录再刷新。

## 板上报文

每行发送一个 UTF-8 JSON 对象，以换行结束：

```json
{"seq":1,"result":85,"status":0}
```

- `result`：唯一必填字段，有限数值。最小报文为 `{"result":85}`。
- `seq`：可选，非负安全整数序号。
- `status`：可选，非负安全整数；0 表示正常，其他值原样显示。
- 其他字段不参与展示。未提供的序号或状态不会被当作 0。

普通文本日志在「原始报文」里展示，不计入数据帧。无效 JSON、错误字段、超长
报文计入异常报文数。每行最多 8192 字符，支持串口分块、CRLF 和 UTF-8 分块。
未以换行结束的最后一条报文不提交；断开时丢弃不完整行。

现有 AM 程序可以使用：

```c
#include <klib.h>

/* 外部数据经 GPIO 读取并处理完成后；seq/result 为程序中的整数变量。 */
printf("{\"seq\":%u,\"result\":%d,\"status\":0}\n", seq, result);
```

现有 AM 格式化输出不提供浮点格式，板上可发送整数或采用约定的定点单位。
只有实现 GPIO 硬件后才可读取 GPIO 寄存器；GPIO 数据在 FPGA 内由程序处理，
UART 只需要输出处理结果。

## 行为与限制

模拟演示以 10 帧/秒生成数据，界面和导出的 `source=demo` 均明确标识模拟来源。
新连接或新演示会覆盖上次会话，有记录时需先确认；断开设备后保留数据。
清空记录也需确认，清空结果会自动保存。暂停冻结显示，但继续采集和保存。
保留最近 10,000 帧，CSV 导出当前保留记录；原始报文最多保留最近 120 行。
图表可显示最近 60、120 或 300 帧，纵轴自动缩放。

UART 默认 115200、8N1、无流控，应与板上配置一致。接线为 FPGA UART TX →
USB 转串口 RX，GND 共地，并使用电平兼容的模块。其他串口工具应先释放端口。

## CNN串口预测（2026-10-31）

新增可选JSON的cnn对象，version=1，pred为三类scores的首个最大值索引，类别固定正常/重心偏移/轴承松动；scores是有符号INT32原始分数，不是概率。包含trained布尔值、64位十六进制model哈希、cycles、rpm_ref（当前620配置）、overruns和scope=experimental。普通result仍为RMS mg，status=0只表示这是一条有效结果，网页单独显示CNN预测，不将它解释为机械健康。

网页保留模型身份、分数及参考转速，支持CSV与JSON备份恢复。CNN模式禁用规则基线C/R按钮；CNN_EVENT非启动事件使当前显示失效并标注旧预测，等下一条有效结果恢复。适配的是预测文本固件，不是WCP1二进制原始采集；二进制继续使用电脑采集工具。35项Node回归包含DOM串口接收、故障覆盖、解析/非法字段/CSV与备份兼容检查。

新增可选cnn.rms_floor（uint32，mg）。当前RMS低于有效下界时，主状态、最新报文及表格统一显示“低振动，暂不判类”，保留原始分数供调试。对旧4174d170模型兼容使用其训练RMS最低值166mg，其他模型由固件提供训练下界。它只提示振幅超出训练覆盖范围，不是停机检测，也不表示机械正常；仍需记录拒判率和运行工况误判。36项Node回归包含7mg串口数据进入页面后的拒判显示。JSON备份保留该字段，原始pred仍是调试用三分类argmax。
